# 案例模版（v1.0）：把一项研究变成平台可用的案例

这份模版解决一个具体问题：**一篇论文/一份报告，怎么变成平台里"能被别人复用"的案例。**
它给三样东西：一套字段（填什么）、一条转换流程（怎么填）、一张验收清单（填对了没有）。

- 可填写的骨架：`templates/case-template/`（`case.card.yaml` + `recipe.yaml` + `README.md`）
- 实例（候鸟—湿地专题）：`core/examples/flightway_wetland/`
- 事实台账写法：`docs/cases/flightway-wetland.md`

---

## 一、先分清四层：案例不是"把文件传上去"

| 层 | 承载什么 | 权威在谁 | 平台做什么 |
|---|---|---|---|
| ① 内容 / 资产层 | 数据、模型、算子的本体 | 各自的提供方 | 只登记地址与访问方式 |
| ② 结构 / 关系层 | GeoKG：实体与关系（**派生**自内容，带血缘） | SDK / GeoKG | 检索与呈现 |
| ③ 元数据契约层 | **GeoCard**：这是什么、能做什么、由哪些资产组成 | SDK（schema 即规范） | 提交、转发审核、镜像状态 |
| ④ 能力 / 执行契约层 | **Recipe**：怎么跑（步骤、参数、交付物） | SDK（`geo.plan` 物化） | 提交运行、登记记录与交付物 |

四层之间是 **derive / describe / operate / reference**，不是"某层是另一层的表示"。

## 二、模版字段

### A. 案例身份（必填）

| 字段 | 说明 | 常见错误 |
|---|---|---|
| `id` | `geocard.case.<主题>-<区域或指标>` | 用论文标题当 id（改不了、也读不出） |
| `name` | 人能读的名字：**做了什么 + 在哪里 + 什么时候** | 只写"某某研究" |
| `description` | 一句话说清结论指向什么，而不是复述摘要 | 把摘要全文粘进来 |
| `type` | `workflow`（组合案例）| 写成 `data`（那样就没有组成与参数契约） |
| `tags` | 主题 + 物种/指标 + 区域 + 数据性质（`synthetic-sample` 等） | 漏标"合成/示意" |
| `provenance.source` | 来源链接/DOI —— **可追溯是案例的底线** | 只写"网络资料" |

### B. 时空范围（必填）

| 字段 | 说明 |
|---|---|
| `spatial.bbox` + `crs` | 案例的**工作范围**。没有空间范围的案例走侧栏，不上地球（不要编一个假位置） |
| `temporal.start/end` | **数据时间**（研究覆盖的时段），与"什么时候跑的"是两件事 |
| 说明 | 若研究是"网络尺度"（跨多国/多点），在 description 里写清"本案例是其中一个节点/窗口" |

### C. 组成 `composition.components[]`（必填）

每一项是**引用**，不是副本：`{id, role, step, required, alias}`。

- `role` 用 GeoCard 词表：`data` / `model` / `skill` / `agent` / `workflow` / `knowledge` / `compute`。
- **只有承载内容的角色参与可见性判定**（`data`/`model`/`knowledge`/`workflow`）。算子与算力不参与：
  它们常常只是名字，把它们算进来会让每个案例都不可见。
- 受限的组成项用 `required: true`（默认）：看不见它的人，也看不见这个案例。
- 可选依赖（`required: false`）缺席不影响可见性，也不影响可运行性。

### D. 参数契约 `params.params[]`（必填，且**只有一份**）

它是"复用"能否成立的关键：没有它，fork 出来的案例是死的。

| 字段 | 说明 |
|---|---|
| `name` | 参数名，与 Recipe 的 `params` **同名同义** |
| `type` | `string/number/integer/boolean/time/bbox/geometry/enum/ref` |
| `required` / `default` | 不给就用作者默认值；必填没给直接 400 |
| `enum` / `minimum` / `maximum` | 取值边界；越界在**物化阶段**就报错，不是跑完才发现 |
| `scope` | `reusable`（复用者可改） / `fixed`（作者钉死，比如"1% 规则"这种定义性参数） |
| `target` | 落到 DAG 的哪里，如 `s1.params.year` |
| `description` | **写清楚为什么**：这个参数的合理范围来自论文的哪一句 |

**原则**：方法链条里的**定义**（阈值规则、指标口径）用 `fixed`；**情境**（区域、年份、窗口）用 `reusable`。
把定义做成可调参数，等于允许别人算出另一个指标还叫这个名字。

### E. 交付物 `outputs[]`（必填）

| 字段 | 说明 |
|---|---|
| `name` / `from` | 交付物名字与来源（`<step>.<output>`）；来源必须真实存在 |
| `role` | 报告是 `knowledge`，数据产品是 `data` |
| `media_type` | 决定平台怎么打开它（`text/html` 可内嵌、`image/tiff` 可上图） |
| `description` | 这个结论是什么，以及**它不能回答什么** |

交付物是**结论**，不是每一步的副产品。中间产物留在运行记录里。

### F. 数据集说明（必填）

| 项 | 说明 |
|---|---|
| 数据槽位表 | 每个输入：现在是什么 → 该换成什么 → 影响哪一步 |
| 合成/示意标注 | 合成数据必须在**文件内部**标注（栅格写 GeoTIFF 标签，表格写首行注释） |
| 数据快照 | `data_snapshot`：这次结论是按哪一版数据算的。没有它，半年后无法区分"结论变了"是因为重跑还是因为数据换了 |

## 三、从研究到案例：七步

1. **抽事实台账**：把研究里的每个数字/结论标出来源（页码/章节），并标注"原文事实 / 我们的推断 / 合成数据"。
   不区分这三类，后面一定会把示意值当成论文值引用。
2. **切出可执行的子链路**：研究里哪些步骤**能算**（指标、统计、遥感）？哪些是**人和制度**（专家核定边界、政策建议）？
   只把能算的做成算子；人和制度的部分显式列为"人工步骤/缺口"，不要假装算法能做。
3. **定数据槽位**：每个输入一行（现在 → 目标 → 影响），拿不到真实数据就用合成数据，并标注。
4. **定参数契约**：区分定义（`fixed`）与情境（`reusable`），把论文里的阈值/口径写进 description。
5. **写 Recipe**：步骤、依赖、`step://` 引用、资源与超时；每一步只做一件事。
6. **声明交付物**：结论级的产出（数据产品 + 报告），并写清局限。
7. **定可见性**：哪些组成项受限？受限项一旦是必需项，整案对外就是 404。

## 四、验收清单

- [ ] `card.validate()` 与 `recipe.validate()` 通过；`recipe_ref` 指向真实方案
- [ ] 参数契约里**没有**"定义性参数"被标成 `reusable`
- [ ] 卡片与方案的 `params` 同名同义（同一份定义，不是两套）
- [ ] 至少端到端跑通一次，且交付物**真的能下载**（不是只有路径）
- [ ] 报告里同时有：结论、方法、来源、**局限**
- [ ] 合成/示意数据在文件内部与报告页首都标注
- [ ] 数据槽位表齐全（现在是什么 → 换成什么 → 影响什么）
- [ ] 可见性：受限组成项在场时，访客看到的是 404（不是 403、不是"部分可见"）
- [ ] 非空间案例：`spatial: false` 进侧栏，不上地球
- [ ] 缺口清单写明：哪些环节没实现（专家核定、政策建议、AI 环节…）

## 五、专题模版怎么套在通用模版上

通用模版定义**字段与流程**；专题模版只加两样东西：

1. **专题参数**：该类研究固定的情境参数（如候鸟—湿地的越冬期、水位阈值、类群筛选）。
2. **交付物集合**：该类研究的固定产出组合（如"水面变化栅格 + 优先地点表 + 报告"）。

专题模版**不改**字段语义，也不新增层。像候鸟—湿地这一版，就是通用模版 + 一份专题参数/交付物清单。

## 六、这套模版现在做不到什么

- **多尺度空间**：一个案例目前是一个 `bbox`。"迁飞网络"这种跨区域对象还没有建模
  （平台侧图层接口能承载多图层，但案例模版还没有"网络"这一层字段）。
- **人工步骤**：专家核定、数据收集这类步骤在 Recipe 里只能写成 `skill` 占位，
  没有"人工任务"的节点类型。
- **运行身份注入**：报告需要知道 `run_id`，目前由执行器补，平台运行路径还没有注入。
- **数据许可**：模版有 `license` 字段，但没有"许可是否允许复用/再分发"的结构化表达。
