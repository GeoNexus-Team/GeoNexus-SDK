## 四、关键决策（谁定的、为什么）

| 决策 | 结论 | 理由 |
|---|---|---|
| 案例定位 | **真能跑**：合成数据 + 现成算子，产出可下载报告 | 用户选择；先证明链路，再谈真实数据 |
| 模版层级 | 通用模版为主 + 候鸟—湿地专题模版作实例 | 用户选择；避免模版只贴合一个案例 |
| 可见性 | 分层：湿地/水位/计数 public，**精确点位 restricted** | 用户选择；且精确点位会指向可被干扰的停歇地 |
| 受限项的 `required` | **true**（默认） | 这样"看不见点位的人"就看不见这个案例（404）—— 公开的壳不能成为绕过受限内容的通道 |
| `one_percent_rule` 参数 | `scope: fixed` | 1% 是**定义**，不是可调阈值；关掉它算出来的不是 PC1 |
| `pc1_threshold` 默认值 | 样例配置 **0.2**（论文校准值 10/1 写进 description） | 样例只有 20 个种群，PC1 量级天然在 0–1；论文的 10 是在 270+ 种群尺度上校准的。写死 10 会让样例"零入选"，看着像失败，其实是尺度差异 |
| 研究区窗口 | 三个示意窗口（黄海—渤海 / 长江中下游 / 三江平原） | 都在原文里被点名；窗口尺度取站点量级 |

## 六、缺口与下一步

1. **地点是点不是面**：论文强调"功能完整的湿地，而不是地图上一条边界"。真实案例需要地点**边界**（面）。
2. **单一 AOI vs 迁飞网络**：本案例跑在一个示意窗口上。"网络"这一层还没有建模 ——
   平台 `/api/cases/:id/layers` 能承载多图层，但案例模版缺"网络/多节点"字段。这是**模版级**的缺口。
3. **人工步骤没有节点类型**：第二步（收集）与第四步（各国专家核定边界）在 Recipe 里只能占位。
4. **运行身份未从平台注入**：报告的 `run_id` 目前由执行器补（`run_case.py`），平台
   `/api/recipes/run` 未注入。SDK 与平台都该补。
5. **真实数据接入**：1% 阈值（EAAF 首次保护状况评估）、AWC/eBird 计数、地点边界三样到位后，
   把 `pc1_threshold` 改回 10 并重跑，才有资格谈结论。

## 七、这篇研究自己承认的局限（报告与案例都必须保留）

- 调查强度不均：**"没有数据"不等于"没有鸟"**，优先名单同时反映鸟类分布与人类调查努力的分布。
- 单次最大数量与多年平均混用，会同时带来高估与低估。
- PC1 不评价栖息地质量、当前威胁与未来开发风险：高分地点可能已接近崩溃。
- 147 处是"当前证据下最有行动价值的组合"，不是永久、封闭的终极名单。
